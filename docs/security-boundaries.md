# قرارداد دامنه و مرز دسترسی

**این سند الزامات طراحی/پیاده‌سازی است، نه ادعای فعال‌بودن کنترل‌ها در اسکلت فعلی.**

- دنا بستر فنی است، نه صادرکنندهٔ مجوز آموزشی. بررسی مدارک ادمین فقط برای دسترسی به پلتفرم است.
- رابطهٔ ناظر با ارائه‌دهنده باید توسط مؤسسه برای **همان دوره** پذیرفته و اعتبارسنجی شود؛ ثبت ادعای ارائه‌دهنده دسترسی ایجاد نمی‌کند.
- نقش و scope حساب/مؤسسه/سازمان/دوره/صندوق در سرور و برای تک‌تک درخواست‌ها کنترل شود؛ پنهان‌سازی UI امنیت نیست.
- سازمان فقط عضو، سفارش و تخصیص مجاز خودش را می‌بیند و گزارش استفاده صرفاً تجمیعی و با حفاظت گروه‌های کم‌جمعیت است.
- خیر فقط پرداخت و رسید خود و گزارش صندوق قابل انتشار را می‌بیند، نه هویت، نمره یا پروندهٔ دریافت‌کننده.
- `/support` درخواست صاحب حساب/نمایندهٔ مجاز و `/admin/support` صف تیم فنی مجازِ همان ماژول است؛ پرسش آموزشی به مؤسسه/ارائه‌دهنده مربوط می‌شود.
- پرداخت، بازپرداخت، تسویه و صندوق باید تأیید معتبر سمت سرور، idempotency و ثبت سوابق داشته باشند. مقدار «—» در Figma به معنی نبود داده است، نه صفر.
- تا پیاده‌سازی مجوز/API، هیچ اکشن غیرواقعی یا تراکنش نمایشی نباید فعال شود.
