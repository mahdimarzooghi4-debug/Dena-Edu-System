# چرخهٔ ثبت جلسهٔ خدمت مؤسسه

این بسته فقط فرادادهٔ زمان‌بندی و وضعیت جلسه را ثبت می‌کند؛ سرور رسانه یا تماس زنده راه‌اندازی نمی‌شود.

## قواعد پیاده‌سازی‌شده

- فقط عضو فعال مؤسسهٔ مسئول می‌تواند جلسه بسازد، شروع کند، پایان دهد یا لغو کند.
- جلسه فقط برای سفارش پرداخت‌شده، دارای سهمیهٔ ثبت‌شدهٔ مثبت و رضایت ثبت‌شدهٔ لازم ایجاد می‌شود.
- زمان برنامه‌ریزی باید در آینده باشد؛ شروع پیش از زمان ثبت‌شده رد می‌شود.
- برای هر سفارش، هم‌زمان حداکثر یک جلسهٔ زمان‌بندی‌شده یا شروع‌شده وجود دارد.
- ایجاد جلسه با کلید idempotency انجام می‌شود. تکرار همان درخواست همان جلسه را برمی‌گرداند و استفادهٔ مجدد از کلید با زمان متفاوت تعارض می‌دهد.
- انتقال وضعیت فقط `scheduled → started → ended` یا `scheduled → cancelled` است. شروع و پایان تکراری idempotent هستند و رویدادها ممیزی می‌شوند.
- زمان و وضعیت جلسه در تاریخچهٔ دانش‌آموز و صندوق مؤسسه نمایش داده می‌شود.

## محدودیت‌های فعلی

این API توکن LiveKit صادر نمی‌کند، جلسهٔ رسانه‌ای ایجاد نمی‌کند، اتصال یا عدم حضور طرفین را تشخیص نمی‌دهد و ضبط ندارد. یک مرز webhook برای adapter آینده و ثبت اتمیک مصرف نهایی آماده شده است: callback باید از بایت خام امضا و ضد replay شود؛ فقط رویداد پایان‌یافته با مقدار صحیح `billableMinutes` پذیرفته می‌شود. مصرف فقط برای سفارش پرداخت‌شده و دارای رضایت لازم، جلسهٔ پایان‌یافته و ماندهٔ کافی ثبت می‌شود؛ تکرار رویداد idempotent است و برای هر جلسه فقط یک رویداد مصرف می‌پذیریم.

تابع ثبت مصرف از زمان‌های شروع/پایان دقیقه نمی‌سازد و گردکردن یا سیاست محاسبه را تعیین نمی‌کند؛ این عدد باید بعداً از adapter مورداعتماد و قاعدهٔ مصوب به دست آید. در حال حاضر هیچ webhook عمومی یا adapter واقعی فعال نیست و مسیر ثبت مصرف به endpoint عمومی متصل نشده است. پیش از تماس واقعی باید قرارداد محاسبهٔ مصرف و انقضا، جریان رضایت معتبر، زیرساخت خودمیزبان LiveKit/TURN و آزمون شبکه تکمیل شوند.
