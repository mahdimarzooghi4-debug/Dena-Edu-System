# آمادگی دیتاست معلم هوشمند دنا — نسخهٔ ۱

**جایگاه فرایند:** Technical → Backlog → Sprint 07 → Code → Code Review → CI/QA.
**وضعیت:** ابزار کنترل ساختار و منشأ داده؛ نه تأیید حقوقی، نه انتخاب مدل، نه اجرای آموزش.
**مبنای محصول:** آموزش آغازین فقط با دیتاست دارای مالکیت/مجوز دنا؛ رشد محتوای مؤسسه در محدودهٔ دانش‌آموزِ دارای دسترسی و به‌صورت جدا از آموزش مشترک.

## هدف بسته

قبل از وجود دیتاست واقعی، یک دروازهٔ آفلاین و قابل‌آزمون بسازیم تا manifest، ارجاع بازبینی حقوق استفاده، hash فایل، رکوردهای JSONL، جداسازی purpose و خطاهای آشکار حریم خصوصی بررسی شوند. ابزار هیچ فایل داده‌ای را به مخزن اضافه نمی‌کند، چیزی را بارگذاری نمی‌کند و مدل را اجرا یا آموزش نمی‌دهد.

## قرارداد manifest

Manifest یک فایل JSON با نسخهٔ `dena-ai-dataset/v1` است و این اطلاعات را نگه می‌دارد:

- شناسهٔ dataset و purpose از میان `dena_initial_training`، `student_context` و `evaluation`.
- نوع و شناسهٔ مالک، ارجاع بازبینی مجوز، نام بازبین و زمان تأیید.
- مسیر نسبی فایل JSONL، SHA-256 مورد انتظار و شمار رکورد.
- برای `student_context`، ارجاع scope دانش‌آموزِ مستعار و غیرهویتی؛ شناسهٔ واقعی دانش‌آموز در این manifest پذیرفته نمی‌شود.

رکوردهای آموزش/ارزیابی دارای `recordId`، `input`، `target`، `sourceRef`، `sourceVersion` و `split` هستند. split برای دیتاست آغازین فقط `train` یا `validation` است؛ برای ارزیابی فقط `evaluation`. رکوردهای زمینهٔ شخصی فقط `recordId`، `text`، `sourceRef` و `sourceVersion` دارند و اصلاً فیلد split/target ندارند. کلیدهای اضافی، پاسخ‌نامه/کلید سؤال و فیلدهای هویتی دانش‌آموز رد می‌شوند.

## قواعد دروازه

- `dena_initial_training` فقط با مالک `dena` و بدون scope فردی پذیرفته می‌شود.
- `student_context` فقط با مالک `institution` و scope مستعارِ دانش‌آموز پذیرفته می‌شود؛ این نوع هرگز خروجی «آمادهٔ آموزش مدل مشترک» نمی‌گیرد.
- `evaluation` از آموزش جدا می‌ماند و نمونهٔ تکراری بین splitها رد می‌شود.
- فایل باید داخل پوشهٔ manifest بماند، regular file باشد و با SHA-256 و شمار رکورد ثبت‌شده منطبق شود.
- محتوای سطرها در گزارش خطا چاپ نمی‌شود. ایمیل/شمارهٔ تلفن آشکار، خطای اعتبارسنجی است؛ این فقط کنترل ابتدایی است و جای بازبینی حریم خصوصی را نمی‌گیرد.
- `rightsReviewRef` فقط ارجاع بازبینی است؛ برنامه نمی‌تواند مالکیت یا صحت مجوز را اثبات کند. بازبین انسانی مسئولیت تصمیم را دارد.

## اجرا

```sh
node scripts/validate-dena-ai-dataset.mjs --manifest /secure/path/manifest.json
```

مسیرها را بیرون از git نگه دارید. ابزار فقط گزارش کدهای خطا، تعداد رکورد و نتیجهٔ hash را چاپ می‌کند. نمونهٔ داده یا manifest ساختگی به‌عنوان دیتاست واقعی دنا تلقی نمی‌شود.

## Backlog و معیار پذیرش Sprint 07

1. تعریف schema بسته و versioned برای سه purpose؛ هر purpose قیود مالک/scope/split خودش را داشته باشد.
2. ساخت validator آفلاین با allowlist سخت، مسیر containment، hash و count بررسی‌شده و سقف اندازه.
3. تست‌های واقعی برای manifest معتبر/نامعتبر، split leakage، رکورد تکراری، hash/count mismatch، traversal، PII آشکار و student context.
4. مستندسازی اجرای محلی و محدودیت‌های حقوقی/فنی؛ هیچ نمونهٔ شخصی یا محتوای آموزشی واقعی در git نباشد.
5. typecheck/lint/unit/build و PostgreSQL/Auth integration CI را برای تغییرات دقیق HEAD بررسی کنیم. CI سبز فقط correctness کد را نشان می‌دهد.

### خارج از محدوده

## وضعیت داده

در شاخهٔ مبنا دیتاست آموزشی واقعی ارائه نشده است. بنابراین این بسته زیرساخت آماده‌سازی و کنترل ورودی را می‌سازد، نه ادعای تکمیل آموزش. پس از دریافت دیتاست و شواهد مجوز، آن مجموعه باید جداگانه بررسی، ارزیابی و با بازبینی انسانی پذیرفته شود.
