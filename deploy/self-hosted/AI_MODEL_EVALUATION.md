# اجرای ارزیابی مدل پایهٔ Dena AI

این راهنما برای اجرای محدود benchmark روی زیرساخت تحت مدیریت دناست؛ سرویس مدل به ترافیک پنل دانش‌آموز وصل نمی‌شود و پاسخ زنده را فعال نمی‌کند.

## مدل و سرویس

- مدل اصلی: `Qwen/Qwen3.5-9B`
- مدل مقایسه: `Qwen/Qwen3.5-4B`
- runtime پیشنهادی برای آزمون: vLLM با API سازگار با Chat Completions.
- پیش از دانلود، دسترسی استفاده/دانلود مدل و شرایط مجوز در تاریخ اجرا ثبت شود. نام مدل به‌تنهایی برای تکرارپذیری کافی نیست؛ revision کامل Git، hash وزن‌ها، نسخهٔ vLLM، قالب گفتگو، پارامترهای تولید و مشخصات GPU باید در گزارش داخلی benchmark ثبت شوند.

مستندات فعلی vLLM خانوادهٔ Qwen3.5 را در مدل‌های پشتیبانی‌شده فهرست می‌کند و API سازگار با Chat Completions ارائه می‌دهد. پشتیبانی runtime جای آزمون نسخهٔ دقیق مدل روی GPU مقصد را نمی‌گیرد.

## مرز شبکه و داده

1. مدل را روی میزبان GPU جدا یا در شبکهٔ خصوصی Docker اجرا کنید؛ پورت آن را عمومی نکنید و از Caddy عمومی دنا عبور ندهید.
2. API key داخلی را از secret manager/فایل secret با دسترسی محدود تأمین کنید. طبق مستند vLLM، API key به‌تنهایی همهٔ مسیرهای HTTP آن را محافظت نمی‌کند؛ شبکهٔ خصوصی و reverse proxy محدودکنندهٔ مسیرها نیز لازم است.
3. مدل را فقط از backend آزمون فراخوانی کنید. متغیر endpoint هرگز در مرورگر یا bundle فرانت‌اند قرار نگیرد.
4. تا آماده‌شدن دیتاست مجاز، فقط fixtureهای مصنوعی و غیرشخصی استفاده شود. دادهٔ آزمون رسمی، پاسخ‌نامه، متن دانش‌آموز، شناسهٔ واقعی و محتوای فاقد مجوز وارد درخواست مدل نشود.
5. case با `active_exam` باید در کنترل برنامه مسدود شود و اصلاً به runtime فرستاده نشود. این الزام را مدل یا prompt اجرا نمی‌کند.
6. ورودی/خروجی کامل مدل در access log یا گزارش عمومی ثبت نشود. گزارش benchmark فقط شناسهٔ case، شناسهٔ مدل و شاخص‌های فنی/کد خطا را نگه دارد؛ متن پاسخ فقط در فضای بازبینی محدود و مصوب بماند.

## گام‌های ارزیابی

1. میزبان GPU را با آزمون بار و حاشیهٔ حافظه انتخاب کنید؛ ظرفیت، quantization، طول context و هم‌زمانی را از روی آزمون واقعی تعیین کنید، نه حدس بر اساس تعداد پارامتر.
2. برای هر دو مدل یک مجموعهٔ ثابت و نسخه‌دار از caseهای synthetic بسازید: `cases.jsonl` طبق قرارداد ارزیاب فعلی و `prompts.jsonl` با هر سطر دارای `caseId`، `prompt` و `context`. شناسه‌ها باید دقیقاً یک‌به‌یک همسان باشند.
3. در صورت اجرای vLLM روی میزبان جدا، یک SSH tunnel به پورت محلی بسازید؛ runner فقط HTTP loopback را می‌پذیرد. نمونهٔ اجرا:

   ```sh
   node scripts/run-dena-ai-model-benchmark.mjs \
     --cases /secure/path/cases.jsonl \
     --prompts /secure/path/prompts.jsonl \
     --responses /secure/path/qwen-9b-responses.jsonl \
     --report /secure/path/qwen-9b-report.json \
     --model Qwen/Qwen3.5-9B \
     --base-url http://127.0.0.1:8000/v1
   ```

   کلید vLLM را پیش از اجرا از secret manager در محیط process قرار دهید؛ آن را در فرمان یا shell history ننویسید. برای 4B همان ورودی‌های نسخه‌دار را به کار ببرید و مسیر خروجی جدا بدهید. runner موردهای `block` را محلی می‌بندد و به مدل نمی‌فرستد. فایل پاسخ و گزارش با مجوز محدود ساخته می‌شوند و فایل خروجی موجود بازنویسی نمی‌شود.
4. ابزار ارزیابی فعلی، citation allowlist، abstention، exam block، سهمیه و canary را روی فایل پاسخ اجرا می‌کند. runner فقط شاخص‌های latency را نیز در گزارش نگه می‌دارد؛ متن prompt و پاسخ را چاپ نمی‌کند.
5. نمونه‌ها را بدون نمایش نام مدل به بازبین آموزشی بدهید تا صحت پاسخ، سادگی، لحن فارسی، تناسب پایه و روش حل را امتیازدهی کند.
6. کیفیت، خطاهای بحرانی، زمان پاسخ، throughput، حافظهٔ اوج و هزینهٔ اندازه‌گیری‌شده را جداگانه گزارش کنید. تنها پس از benchmark محتوای آموزشی واقعیِ دارای مجوز و بازبینی انسانی، دربارهٔ عرضه تصمیم بگیرید.

## وضعیت فعلی

- این محیط توسعه GPU و وزن مدل ندارد؛ این راهنما به معنی دانلود مدل یا اجرای inference نیست.
- runner فقط روی loopback کار می‌کند تا promptها به host عمومی فرستاده نشوند؛ برای GPU remote از SSH tunnel استفاده کنید.
- دیتاست آموزشی واقعی دنا در مخزن موجود نیست؛ fixture مصنوعی فقط برای آزمون pipeline قابل استفاده است.
- هیچ اتصال مدل به endpoint دانش‌آموز یا مصرف اعتبار فعال نشده است.
