# دنا | Dena Edu System

دنا (دانش‌آموزان نوآفرین ایران) **بستر فنی** آموزش ضبط‌شده، تمرین، آزمون و پیگیری یادگیری است؛ مؤسسهٔ آموزشی یا صادرکنندهٔ مجوز رسمی نیست. محتوای آموزشی و نظارت هر دوره با مؤسسه/ارائه‌دهندهٔ مسئول همان دوره است.

## پشتهٔ تأییدشده

Next.js App Router + React + TypeScript؛ Tailwind CSS 4 + قرارداد shadcn/ui؛ PostgreSQL + Drizzle ORM؛ Better Auth؛ React Hook Form + Zod؛ Vitest + Playwright. جزئیات پشته در [ADR-0001](docs/decisions/0001-technology-stack.md) و هدف معماری مقیاس‌پذیر برای پنج میلیون کاربر همزمان در [ADR-0002](docs/decisions/0002-five-million-concurrent-architecture.md) و برنامهٔ ارزیابی زیرساخت ایران و رشد مرحله‌ای در [ADR-0003](docs/decisions/0003-iran-deployment-and-capacity-rollout.md) آمده است؛ ظرفیت هدف هنوز با تست بار و قرارداد CDN/زیرساخت تأیید نشده است.

## راه‌اندازی توسعه

Node.js 22 و npm 11 پیشنهاد می‌شود. npm 10.9.8 در نخستین نصب این مجموعه وابستگی با خطای `edgesOut` متوقف شد؛ نصب npm 11 و تولید lockfile در GitHub Actions موفق بود.

```sh
npm ci
npm run dev
npm run typecheck
npm run lint
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

فایل `package-lock.json` از رجیستری npm تولید و ثبت شده است. CI با `npm ci` نصب می‌کند و lint، typecheck، unit test، build و smoke test مرورگری را اجرا می‌کند.

## بررسی ایستای پیکربندی پیش از انتشار

`npm run check:release-config` فقط متغیرهای لازم برای انتشار **تمام قابلیت‌ها** را بدون چاپ مقدار secret بررسی می‌کند؛ حالت mock/localhost/HTTP یا reuse کلیدهای حساس را رد می‌کند؛ برای PostgreSQL نیز ‎`sslmode=verify-full`، نام میزبان غیرمحلی و ‎`NODE_ENV=production` می‌خواهد. غیرفعال‌کردن سراسری بررسی گواهی TLS نیز رد می‌شود. این بررسی TLS را واقعاً مذاکره نمی‌کند یا اصالت گواهی را نمی‌سنجد. این دستور در CI mock عمداً اجرا نمی‌شود و عبور آن به معنی اتصال SMS واقعی، انجام آنتی‌ویروس یا آمادگی ۵ میلیون کاربر نیست. [چک‌لیست عملیاتی و خلاصهٔ قابل تحویل](docs/implementation/release-readiness-handoff.md).

## وضعیت واقعی پیاده‌سازی

- صفحهٔ اصلی `/` پوستهٔ عمومی را معرفی می‌کند.
- مسیرهای `/preview/student`، `/preview/institute`، `/preview/provider`، `/preview/admin`، `/preview/organization` و `/preview/benefactor` **پیش‌نمایش عمومی و بدون دادهٔ عملیاتی** هستند. `/preview/support` پوستهٔ ثابت پیش‌نمایش است؛ پشتیبانی متصل به حساب در `/support` و inbox اپراتور مجاز در `/admin/support` قرار دارد.
- پوستهٔ مشترک فقط با هدف‌گذاری موبایل و دسکتاپ طراحی می‌شود: در دسکتاپ نوار کناری ۲۷۲ پیکسلی مطابق Figma و در موبایل منوی بازشوندهٔ قابل استفاده با صفحه‌کلید دارد؛ تست Playwright برای عرض‌های موبایل ۳۷۵ و ۳۹۰ و دسکتاپ ۱۴۴۰ پیکسل اضافه شده است. نسخهٔ اختصاصی تبلت در محدودهٔ پروژه نیست.
- قراردادهای نقش و دسترسی به دوره، گزارش تجمیعی سازمان، رسید/صندوق خیر و تیکت فنی ثبت شده‌اند: [قراردادهای دسترسی](docs/access-contracts.md). تیکت فنی مشترک در `/support` به Better Auth و PostgreSQL متصل است؛ فقط admin دارای پرچم صریح `canHandleTechnicalSupport` می‌تواند از `/admin/support` رسیدگی کند. پرداخت و صندوق هنوز endpoint عملیاتی ندارند.
- داشبورد پیش‌نمایش دانش‌آموز از نظر ساختار (بنر، سه کارت نمای کلی، دوره‌ها، تمرین/آزمون و مسیر رشد) به فریم `153:2` فیگما نزدیک شده؛ درصدها، عناوین دوره‌ها، نام مؤسسه و شمارش نمایشی فیگما **عمداً منتقل نشده‌اند**.
- رنگ‌ها و ابعاد پایه از Figma گرفته شده‌اند و لوگوی کوچک مستقیماً از فریم تصویب‌شدهٔ آن صادر شده است. Vazirmatn Variable و Estedad Variable از بسته‌های نسخه‌ثابت Fontsource تحت OFL-1.1 به‌صورت self-hosted بسته‌بندی می‌شوند: [اسناد فونت و مجوز](docs/font-licenses.md). QA بصری کامل و همهٔ فریم‌ها هنوز باقی مانده‌اند.
- مسیر `/benefactor` اکنون **خانهٔ محدود واقعی خیر و حامی** است: صرفاً هویت‌های حامی دارای عضویت فعال و entity تأییدشدهٔ همان نقش را از PostgreSQL و API خواندنی `/api/benefactor/overview` نمایش می‌دهد؛ مرجع محرمانهٔ مدارک، هویت دریافت‌کننده و دادهٔ خیر دیگر قابل مشاهده نیست. صندوق حمایت، پرداخت، تخصیص کمک، رسید و گزارش هزینه‌کرد هنوز پیاده‌سازی عملیاتی ندارند؛ هیچ مبلغ یا گزارش فرضی نمایش داده نمی‌شود.
- مسیر `/organization` اکنون خانهٔ محدود واقعی سازمان است. `/organization/students` پرونده‌های همان سازمان را از فرم دستی، فایل CSV/Excel یا API می‌سازد؛ کدملی با AES-256-GCM رمز می‌شود و فقط چهار رقم پایانی نشان داده می‌شود. حساب ورود از ابتدا ساخته می‌شود اما تا OTP خود دانش‌آموز تأیید نشده می‌ماند. کلید API یک‌بار نمایش داده و فقط هش آن ذخیره می‌شود؛ چرخش/لغو فوری و سقف ۶۰ درخواست در دقیقه دارد. کاربر سازمانی می‌تواند با تأیید صریح، فقط پروندهٔ خودش را از محدودهٔ سازمان حذف کند؛ حساب عمومی دانش‌آموز باقی می‌ماند. تخصیص دوره، گزارش تجمیعی مصرف و سفارش/صورتحساب هنوز عملیاتی نیستند. جزئیات و محدودیت‌ها در [قرارداد ثبت دانش‌آموز سازمان](docs/implementation/organization-student-provisioning-v1.md) آمده است.
- مسیر `/admin` داشبورد محدود واقعی با شمار نقش‌ها، دوره‌ها، وضعیت‌های supervision/practice/learning assessment و رویدادهای اخیر است؛ `/admin/audit` گزارش محدود رویدادها را می‌دهد و صف بررسی نقش مستقل باقی می‌ماند. طرح داشبورد ادمین اکنون در صفحهٔ `07 — Admin Panel V1` فایل Figma آمده است. مدیریت کاربران و مالی فعال نیستند. رسیدگی تیکت جداست و فقط از `/admin/support` برای اپراتور صریحاً مجاز انجام می‌شود.
- مسیر `/institute` اکنون **خانهٔ محدود واقعی مؤسسه** است: دوره‌های مربوط به scopeهای فعال خود مؤسسه، وضعیت نظارت/انتشار و تعداد واقعی ارزیابی‌های یادگیری به تفکیک وضعیت بازبینی را از PostgreSQL نمایش می‌دهد. شمار در انتظار فقط دوره‌های پیش‌نویسِ تحت نظارت و همین ۲۰ ردیف را دربرمی‌گیرد؛ پیوند مستقیم به بازبینی ارزیابی همان دوره دارد. اطلاعات شخصی یا تلاش‌های دانش‌آموز در خانه نمایش داده نمی‌شود.
- مسیر `/provider` اکنون **خانهٔ محدود واقعی ارائه‌دهنده** است: فقط دوره‌های محدودهٔ فعال او با وضعیت فعلی نظارت و انتشار در PostgreSQL نشان داده می‌شوند؛ دریافت ویدئوی آزمایشی تنها برای دورهٔ پیش‌نویس با نظارت تأییدشده لینک دارد. درآمد، آمار دانش‌آموزان و آزمون هنوز عملیاتی نیستند.
- مسیر `/student/privacy` و API خصوصی `/api/student/private-notes` امکان **شمارش و حذف صریح همهٔ یادداشت‌های ویدئوییِ خود دانش‌آموز** را می‌دهند؛ حتی یادداشت‌های باقی‌مانده پس از لغو ثبت‌نام، لغو نظارت یا برداشته‌شدن ویدئو. حذف فقط با نشست دانش‌آموز فعال، Origin هم‌دامنه و عبارت تأیید مخصوص API انجام می‌شود، بدون افشای متن یا شناسه ویدئو در نمای پاک‌سازی و بدون تغییر علامت‌های «انجام‌شده» یا یادداشت دیگران. این حذف مربوط به رکوردهای جدول یادداشت در DB فعال است؛ حذف نسخه‌های پشتیبان، دیگر داده‌های حساب، سیاست نگهداری و گردش‌کار حقوقی کودک هنوز پیاده‌سازی/تأیید نشده‌اند.
- صفحهٔ مشاهدهٔ ویدئو اکنون **یادداشت شخصی هر ویدئو** دارد: `dena_student_video_notes` در migration `0011` و API خصوصی PUT/DELETE با طول ۱ تا ۲۰۰۰ نویسه، فقط برای دانش‌آموز دارای ثبت‌نام/نظارت/ویدئوی آمادهٔ معتبر؛ متن فقط در manifest و watch خود دانش‌آموز دیده می‌شود، نه پنل ارائه‌دهنده/مؤسسه، API پیگیری تجمیعی یا گزارش خیر/سازمان. حذف یادداشت مستقل از علامت انجام‌شده است؛ پس از لغو دسترسی امکان خواندن/تغییر آن از API وجود ندارد. سیاست نگهداری/حذف دادهٔ کودکان برای استقرار واقعی هنوز نیازمند بررسی حقوقی است.
- مسیر `/student/progress` و API خصوصی `/api/student/progress` اکنون شمار واقعی علامت‌های خوداظهاری ویدئوهای آماده را برای حداکثر ۲۰ دورهٔ اخیرِ دارای ثبت‌نام و مجوز فعلی، به تفکیک دوره، از PostgreSQL محاسبه می‌کنند؛ دوره یا ویدئوی لغوشده/برداشته‌شده در آمار فعلی دیده نمی‌شود. مجموع بالای صفحه **صرفاً شامل همین دوره‌های نمایش‌داده‌شده** است؛ این اعداد نمره، اثبات تماشا یا گزارش رسمی یادگیری نیستند.
- مسیر `/student/courses/[courseId]/watch` اکنون **علامت خوداظهاری انجام‌شدن هر ویدئو** دارد: در PostgreSQL برای هر دانش‌آموز/ویدئوی آماده و مجاز یک رکورد یکتا نگه می‌دارد؛ امکان برداشتن علامت و نمایش وضعیت فعلی در manifest خصوصی فراهم است. این علامت با session، ثبت‌نام فعال و نظارت همان دوره سنجیده می‌شود، اما **اثبات تماشا، نمره، آزمون یا درصد پیشرفت خودکار نیست**. صندوق ارزیابی و گزارش رسمی همچنان ساخته نشده‌اند.
- مسیر `/student/progress` اکنون نتیجهٔ **همان یک تمرین تأییدشدهٔ هر دوره** را کنار شمارش علامت‌های خوداظهاری نشان می‌دهد: هنوز پاسخ نداده، گزینه و درست/نادرستِ پاسخ ثبت‌شدهٔ خودت، یا نبود سؤال تأییدشده. مجموع تمرین‌های پاسخ‌داده‌شده فقط برای حداکثر ۲۰ دورهٔ فعلاً مجاز و نمایش‌داده‌شده حساب می‌شود. کلید درست، سؤال رد/معلق، تلاش دانش‌آموز دیگر و اطلاعات محرمانهٔ ارائه‌دهنده/بازبین در پاسخ دیده نمی‌شوند. این شمار، نمرهٔ رسمی یا گواهی نیست؛ متن توضیحی صفحهٔ تمرین نیز با بازبینی مستقل مؤسسه هماهنگ شد.
- مسیر `/student/growth` روند درصد پاسخ درست تلاش‌های ارسال‌شده برای ارزیابی‌های تأییدشده را از backend خود دانش‌آموز می‌خواند؛ هر سری به همان ارزیابی محدود است و بین دوره‌ها/ارزیابی‌ها مقایسه نمی‌شود. صفحه فرض هم‌ترازی دشواری نسخه‌های تصادفی سؤال را آشکار می‌کند؛ این درصد نمرهٔ رسمی یا اثبات یادگیری نیست. جزئیات در [قرارداد روند ارزیابی دانش‌آموز](docs/implementation/student-growth-trend-v1.md) آمده است.
- **اولین تمرین چهارگزینه‌ای واقعی دوره** اکنون در پایگاه داده وجود دارد: migration `0012` سؤال/تلاش را ایجاد کرد و migration `0013` بازبینی مستقل مؤسسه را اضافه می‌کند. ارائه‌دهنده فقط در پیش‌نویسِ دارای نظارت فعال یک سؤال تغییرناپذیر و پاسخ درست ثبت می‌کند؛ سؤال با `pending` شروع می‌شود و تا تأیید/رد جداگانهٔ نمایندهٔ فعالِ مؤسسهٔ مسئول در `/institute/courses/[courseId]/practice` به دانش‌آموز نمایش داده نمی‌شود. فردی که هم‌زمان provider همین دوره باشد نمی‌تواند reviewer همان سؤال باشد. وجود سؤال `pending` انتشار دوره را با 409 متوقف می‌کند؛ سؤال rejected پنهان می‌ماند و سؤال approved بعد از entitlement واقعی در watch قابل پاسخ است. نمره‌گذاری همین سؤال سمت سرور و تک‌تلاش است؛ پاسخ‌ها و هویت دانش‌آموزان به reviewer/provider نمایش داده نمی‌شوند. این تمرین اختیاری نه آزمون رسمی/نمرهٔ مدرسه است و نه مدرک یا اثبات تماشا.
- هر دورهٔ رایگانِ منتشرشده و دارای نظارت معتبر اکنون **صفحهٔ جزئیات واقعی `/student/courses/[courseId]`** دارد: نام ثبت‌شدهٔ ارائه‌دهنده و مؤسسهٔ مسئولِ همان دوره، شمار ویدئوهای `ready` و وضعیت ثبت‌نام خود دانش‌آموز (فعال/لغوشده/هنوز ثبت‌نام نکرده) را از PostgreSQL می‌خواند. API خواندنی `/api/student/courses/[courseId]` و صفحه فقط با نقش دانش‌آموز و `listedFreeCourse` کار می‌کنند؛ شناسه، عنوان و مسیر فایل خصوصی پیش از ثبت‌نام، مدارک بررسی محرمانه و اطلاعات دیگر دانش‌آموزان فاش نمی‌شوند. ثبت‌نام از همین صفحه از endpoint قبلیِ رایگان با اعتبارسنجی مجدد انجام می‌شود؛ دورهٔ لغوشده از این مسیر خودکار بازفعال نیست. تأیید نظارت دنا به‌معنی گواهی/مجوز رسمی نیست.
- کاتالوگ واقعی `/student/courses` اکنون جست‌وجوی عنوان، فیلتر «فقط ثبت‌نام‌های من» و صفحه‌بندی سروری ۲۰تایی (`nextCursor`) دارد؛ شرط‌های واقعی انتشار، نظارت، عضویت و ویدئوی آماده در هر صفحه اعمال می‌شوند و ۵۰ نتیجهٔ اول سقف دید کاربر نیست. فیلتر شخصی تنها ثبت‌نام فعال همان دانش‌آموز را نشان می‌دهد. جست‌وجوی پیشرفته فارسی، snapshot کاتالوگ و load testing هنوز بازند.
- مسیر `/student` اکنون **خانهٔ دانش‌آموز متصل به PostgreSQL** است: پس از session و نقش فعال، فقط دوره‌های ثبت‌نام‌شدهٔ خود کاربر که همچنان منتشر، تحت نظارت معتبر و دارای ویدئوی آماده‌اند در فهرست اخیر نمایش داده می‌شوند؛ فقط آمار علامت‌های واقعیِ خوداظهاری از مسیر جداگانهٔ پیگیری نشان داده می‌شود؛ اطلاعات ارزیابی ساختگی نمایش داده نمی‌شود. **پنل‌های کامل عملیاتی نقش‌ها** هنوز پیاده‌سازی نشده‌اند؛ صفحات محدود گردش‌کار، جایگزین پنل کامل نیستند. نقشهٔ `src/lib/navigation.ts` قرارداد طراحی است، نه مجوز دسترسی.
- صفحهٔ فارسی RTL `/login` و صفحهٔ محافظت‌شده `/account` به کد اضافه شده‌اند: دو مرحلهٔ شماره/کد، نمایش وضعیت خطا/ارسال، ورودی ارقام فارسی، خروج از نشست و نمایش فقط نقش‌های خوانده‌شده از سرور. رابط از فونت، رنگ و Card/Button مشترک دنا استفاده می‌کند؛ فریم مستقل لاگین در Figma هنوز برای QA بصری نهایی تعیین نشده است. بدون سرویس SMS فرم ورود غیرفعال و شفاف است.
- فرایند اولیه درخواست و بررسی نقش‌های مؤسسه، ارائه‌دهنده، سازمان و خیر به `/account/role-applications` و `/admin/role-applications` اضافه شده است. فقط ادمین فعال می‌تواند **پس از بررسی دستی مدارک و با دلیل و شناسه مرجع محرمانه** درخواست شخص دیگری را تأیید/رد کند؛ تأیید در یک تراکنش، رکورد دامنه جدید، membership محدود و رویداد ممیزی ایجاد می‌کند. نقش ادمین از ثبت‌نام قابل درخواست/دریافت نیست و bootstrap امن اولین ادمین هنوز عملیاتی نشده است. [شرح مرزها و تست‌ها](docs/implementation/privileged-role-review.md). اعطای نقش مؤسسه/ارائه‌دهنده به‌تنهایی تأیید نظارت همان دوره نیست.
- **دریافت ویدئوی آزمایشی با قرنطینه** در مسیر `/provider/courses/[courseId]/media` و APIهای provider/worker اضافه شده است: رزرو یکتا با digest/size و شناسه‌های فایل سرورساخت، انتقال MP4 کوچک با کنترل مجدد scope/grant، وضعیت quarantine، و فقط پس از گواهی origin و callback مستقل دارای Bearer، ساخت asset آماده در transaction. گزارش JSON بازرسی origin پیش از parse به ۴KiB محدود می‌شود و پاسخ بزرگ/خراب نمی‌تواند asset آماده ایجاد کند. **آنتی‌ویروس، transcoding و مخزن واقعی هنوز پیاده یا متصل نشده‌اند**؛ شبیه‌ساز CI به‌جای scanner معتبر نیست و upload در `.env.example` پیش‌فرض خاموش است. این مسیر حافظه‌ای سقف ۸MiB طرح نهایی video/CDN یا بار همزمان ملی نیست. [مرزهای پایلوت ingest](docs/implementation/quarantined-media-ingest.md).
- ثبت‌نام رایگان دانش‌آموز و محتوای MP4 خصوصی در API و صفحه‌های `/student/courses` و `/student/courses/[courseId]/watch` به‌صورت **مرحله آزمایشی متصل به PostgreSQL** اضافه شده است. فقط دوره published با نظارت approved همان مؤسسه، نماینده/ارائه‌دهنده فعال و asset آماده در فهرست می‌آید؛ ثبت‌نام unique/idempotent و فقط برای خود دانش‌آموز است و لغو خودکار بازفعال نمی‌شود. مسیر ویدئو روی هر درخواست byte-range، session و enrollment و grant را بررسی می‌کند؛ همچنین قبل از stream برابری `Content-Range` و `Content-Length` با پاسخ ۲۰۶ و خصوصی‌بودن origin را می‌سنجد؛ runtime آدرس HTTPS محلی/loopback/link-local برای origin خصوصی را رد می‌کند، اما آدرس خصوصی RFC1918 برای زیرساخت داخلی مجاز می‌ماند؛ هیچ origin URL یا token به مرورگر تحویل نمی‌شود. مسیر آزمایشی ingest با quarantine و شبیه‌ساز CI اضافه شده اما scanner/transcoding، مخزن و CDN واقعی **هنوز وجود ندارد**؛ این proxy از Next.js برای مقیاس پنج میلیون همزمان طراحی/آزموده نشده است. [شرح مرز ویدئو و ثبت‌نام](docs/implementation/free-student-enrollment-private-video.md).
- رابطه نظارتی مؤسسه/ارائه‌دهنده **اکنون به‌ازای هر دوره در API و PostgreSQL پیاده‌سازی اولیه دارد**: `/provider/supervision` ایجاد دوره و درخواست با کلید idempotency، `/institute/providers` بررسی مستقل تأیید/رد/لغو، و مجوز نمای نظارتی تنها در وضعیت approved همان دوره. رویدادهای تصمیم و foreign key مرکب scope در migration ثبت شده‌اند. این دو مسیر، صرفاً گردش‌کار محدود واقعی هستند نه پنل‌های کامل یا اجازه پخش دانش‌آموز؛ [قرارداد نظارت هر دوره](docs/implementation/course-supervision-workflow.md).
- **ورود موبایلی OTP با آداپتور SMS قابل تعویض اضافه شده، اما پیش‌فرض خاموش است:** شماره موبایل canonical ایرانی، کد شش‌رقمی پنج‌دقیقه‌ای، سقف تلاش و ارسال پایدار بین instanceها، و تخصیص فقط عضویت دانش‌آموز به مالک شمارهٔ تأییدشده؛ نقش‌های ممتاز از خوداظهاری داده نمی‌شوند. تا انتخاب SMS و اجرای پایلوت، پیامک عملیاتی به کاربران ارسال نمی‌شود. ارسال OTP هرگونه redirect (از جمله ۳۰۷/۳۰۸) را رد می‌کند تا کد و شماره به مقصدی دیگر ارسال نشوند؛ خطای gateway بدون بازتاب دادهٔ حساس پاسخ داده می‌شود؛ تأیید موفق تنها با پاسخ JSON محدود و `{"accepted":true}` از درگاه پذیرفته می‌شود، نه صرفاً HTTP 2xx؛ HTTPS به localhost/loopback یا IP متادیتای link-local نیز در زمان اجرا رد می‌شود (به‌جز mock محلی CI). کنترل واقعی DNS/egress هنوز گیت استقرار است. [قرارداد و گیت‌های امنیتی](docs/implementation/mobile-otp-onboarding.md).
- **پایه DB/هویت در کد اضافه شده، نه راه‌اندازی نهایی:** schema و adapterهای PostgreSQL/Drizzle/Better Auth و APIهای هویت/مجوز وجود دارند؛ migrationهای `0000` تا `0018` ثبت شده‌اند. دیتابیس دائمی، credentials امن و محیط عملیاتی/OTP همچنان راه‌اندازی نشده‌اند. پیامک واقعی تا انتخاب provider خاموش است، و ثبت‌نام/stream فقط برای دورهٔ رایگان با origin خصوصی در محیط integration فعال است؛ پرداخت، scanner/transcoder/CDN واقعی و صندوق حمایت هنوز فعال نیستند. تیکت فنی در سطح محدودِ مالک و اپراتور مجاز پیاده شده؛ جزئیاتش در [مستند پشتیبانی فنی](docs/implementation/technical-support.md) است. [راهنمای راه‌اندازی و محدودیت‌ها](docs/implementation/auth-database-foundation.md). `.env.example` فقط جای متغیرهاست؛ کلید و دادهٔ محرمانه commit نکنید.

**قبل از عرضهٔ پنل‌های واقعی:** برای هر درخواست role + scope سروری را اعتبارسنجی کنید، نظارت را برای هر دوره تأیید کنید، خروجی سازمان را تجمیعی و محفوظ و دسترسی خیر را محدود کنید. جزییات در [مرزهای امنیتی](docs/security-boundaries.md).
